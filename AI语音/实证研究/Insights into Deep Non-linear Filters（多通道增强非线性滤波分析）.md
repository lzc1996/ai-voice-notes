# Insights into Deep Non-linear Filters（多通道增强非线性滤波分析）

> [!abstract] 这页的角色
> 这是**机制分析型论文证据页**：它不提出新任务或新指标，核心贡献是用受控实验拆开"空间 / 频谱 / 时间"三类信息源，回答深度非线性滤波为什么有效。分析产物是 [[方向/AI语音/模型/FT-JNF（Frequency-Time Joint Non-linear Filter）|FT-JNF]] 架构——模型身份见模型页，本页只记录证据链、数字和边界。

## 1. 研究问题

传统多通道增强把**线性空间滤波（波束形成）**与**单通道后滤波**分两步做；DNN 可以学一个联合空间—时频的非线性滤波器（JNF），但"为什么有效"不清楚。论文要回答三个问题：

1. 性能主因是**非线性空间滤波**，还是 DNN 建模能力本身？
2. 空间处理与**时频后处理**能否分离？联合处理是否必要？
3. **频谱信息**与**时间信息**对空间滤波的贡献是否对等？

## 2. 核心假设

| 假设 | 内容 | 验证方式 | 论文结论 |
| ---- | ---- | -------- | -------- |
| H1 | 非线性空间滤波本身带来增益，不只是"DNN 参数估计 + 线性模型" | 非线性空间滤波 vs oracle 参数 MVDR | 成立（低麦克风数） |
| H2 | 空间与时频处理相互依赖，分离会损失信息 | JNF vs NSF+PF vs LSF+PF | 成立 |
| H3 | 频谱与时间信息贡献不对等，且取决于任务/数据 | F/T 变体受控对比 | 成立，但方向随数据集反转 |

## 3. 实验设计

### 3.1. 三种处理结构（对应假设）

- **(a) LSF + PF**：线性空间滤波（oracle MVDR）→ 单通道后滤波。
- **(b) JNF**：一个网络同时做空间与时频非线性滤波（论文主张的 MMSE 最优形态）。
- **(c) NSF + PF**：非线性空间滤波 → 独立后滤波。

对比 (a)/(c) 检验"非线性空间滤波"的价值，对比 (b)/(c) 检验"联合处理"的价值。

### 3.2. 信息源控制（关键设计）

基座网络极简：两层 bi-LSTM + 一层 FF + tanh，输出 cIRM，作用于参考通道。通过**输入数据的排列方式**控制网络能看到什么：

- **宽带排列（F）**：频率作序列维，网络可看细粒度频谱结构。
- **窄带排列（T）**：时间作序列维，网络可看细粒度时间结构（Li & Horaud 的原方案）。
- **FT-JNF**：第一层 LSTM 用宽带排列，之后切到窄带排列，两层之间切换——同时获得空间、频谱、时间信息。
- **NSF 变体**：在进 LSTM 前沿序列维随机置换、出 FF 前逆置换，网络只能看到**全局统计**，无法利用相邻频点/帧的相关性；宽带版额外拼接频点索引。

### 3.3. 数据与训练

- **说话人提取集**：pyroomacoustics 仿真，WSJ0 语音；4 麦圆阵（直径 10 cm，可 2–5 麦）；目标固定在阵列朝向 0°，五个干扰说话人分布在其余扇区；T60 0.2–0.5 s，平均 SNR −4 dB（95% 样本 −9~2 dB）；6000 / 1000 / 600 条。
- **CHiME3**：真实四环境（cafeteria / bus / pedestrian / street），6 麦平板阵列取后 4 通道；2400 / 476 / 3251 条；测试 SNR {−4, 0, 4, 8} dB。
- 训练：cIRM + Tolooshams 等时频 ℓ1 损失（α = 10），32 ms √Hann 窗、50% 重叠，Adam lr 0.001，最多 250 epoch。
- 指标：POLQA（质量）、ESTOI（可懂度）、MUSHRA CQS（主观）。

### 3.4. 方向选择性探针

除整体指标外，论文把**干净无混响语音**从不同入射角送入训练好的滤波器，用 POLQA 分数当"通过/抑制"的代理画方向响应；以及用白噪声测 STFT 平均响应。这是区分"空间选择性"与"时频增强"的关键手段。

## 4. 结果

### 4.1. 非线性空间滤波 vs oracle 线性滤波（H1）

- oracle 参数 MVDR 是线性空间滤波的上界；**非线性空间滤波（FT-NSF）在低麦克风数下 POLQA 更高**，尽管它会较激进地压噪声并引入语音失真。
- 行为差异：MVDR 无失真但抑制不足；NSF 抑制强但伤语音。
- 摘要口径：低麦克风数说话人提取场景，非线性空间处理比 oracle 线性空间滤波高 **0.24 POLQA**。

### 4.2. 空间与时频不可分（H2）

- **FT-NSF + PF ≈ FT-NSF**（几乎没有提升）：空间阶段丢掉的语音信息，后滤波掩码无法恢复。
- 对比之下，**MVDR + PF** 相对 MVDR 提升 0.18（2 麦）~ 0.5（3 麦）POLQA——因为 MVDR 不伤语音。
- **FT-JNF > LSF + PF**，2 麦时差距达 **0.44 POLQA**；麦克风数增加时差距缩小甚至反转（oracle MVDR 可消的方向源数随麦数增加）。

### 4.3. 频谱 vs 时间信息（H3，3 麦，相对未处理的提升）

| 变体 | ΔPOLQA | ESTOI |
| ---- | ------ | ----- |
| F-NSF | 0.78 | 0.62 |
| T-NSF | 0.46 | 0.54 |
| FT-NSF | 0.87 | 0.64 |
| F-JNF | 1.15 | 0.70 |
| T-JNF | 0.74 | 0.63 |
| **FT-JNF** | **1.43** | **0.76** |

- 空间滤波从**频谱**信息获益远大于从**时间**信息：F-NSF vs T-NSF 差 0.32 POLQA；F-JNF vs T-JNF 差 0.41 POLQA / 0.07 ESTOI。
- 方向选择性探针显示：用频谱信息的滤波器在目标方向外抑制更强，且选择性窄于训练集设定的 ±20° 扇区。

### 4.4. 与 SOTA 对比

- 说话人提取：FT-JNF 比五个基线（T-JNF、CRNN、FaSNet+TAC、EaBNet、COSPA）至少高 **0.22 POLQA / 0.04 ESTOI**；MUSHRA CQS **67.9**，第二名 EaBNet **53.1**（11 人、12 条样例）。
- 参数量：FT-JNF **1.2M**，低于 CRNN 17.4M、FaSNet+TAC 4.1M、EaBNet 2.8M、COSPA 2.1M——参数量不是决定因素。
- CHiME3（POLQA 提升，BUS/CAF/PED/STR）：FT-JNF **1.53 / 1.56 / 1.45 / 1.76**，对比 EaBNet 1.19 / 1.18 / 1.08 / 1.31；摘要口径领先 **0.32 POLQA**。

## 5. 意外现象

1. **后滤波救不回空间阶段的损伤**：非线性空间滤波后再接独立后滤波几乎零收益，而 MVDR 后接后滤波收益很大——说明信息损失发生在空间阶段，而非"后处理不够强"。
2. **CHiME3 上收益反转**：说话人提取集里频谱信息更重要，CHiME3 上却是**时间信息**（T-JNF > F-JNF）。作者归因于 CHiME3 噪声的时频结构与语音差异大、更平稳，单通道时频增强已能拿分，空间选择性不是瓶颈。
3. **CHiME3 的提升不能归因于空间滤波**：方向探针显示该数据集的目标位置相对阵列近似固定（说话人举着平板），性能提升主要来自时频处理——只看总分会把结论归错。
4. **波束形成式架构不占优**：模仿 filter-and-sum 的 EaBNet 参数更多、却不如极简的掩码式 FT-JNF；且在 0° 目标方向上也损伤干净语音。
5. **选择性窄于训练分布**：频谱信息让滤波器在 ±20° 训练无干扰区之外仍有抑制，属于超出训练配置的外推行为。

## 6. 可复用结论

- **先组织信息源，再堆模块**：宽/窄带排列决定了网络能利用哪类相关性；同样的层数和参数量，排列不同结果差 0.4+ POLQA。
- **联合优于分步**：多通道前端若先做不可逆的空间压缩、再交给单通道后处理，会浪费非线性空间处理的潜力。
- **评估多通道模型要做方向探针**：整体 POLQA/ESTOI 无法区分"空间选择性"与"时频增强"，探针实验是必要补充。
- **参数量不是主因**：1.2M 的简单架构胜过 2–17M 的复杂基线，架构对信息流的安排更关键。

## 7. 边界

- 受控架构只有两层 bi-LSTM + FF，结论是关于**信息源组织**的，不构成对任意架构的普适排名。
- 说话人提取集目标固定在阵列 0° 朝向，CHiME3 目标位置也近似固定；空间选择性结论依赖该设置。
- 非因果（bi-LSTM），未报告流式/低延迟版本。
- 指标为 POLQA / ESTOI / MUSHRA，**没有下游 ASR WER**；POLQA 需授权。
- 基线的超参搜索有限（主要调学习率、用作者默认配置），不代表各基线的最佳性能。
- "0.24 POLQA 优于 oracle MVDR"是 oracle 参数上界口径，不等于优于任何实用 MVDR 实现。
