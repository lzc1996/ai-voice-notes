# Distributed Multichannel SE（分布式异步多通道增强）

分布式 / 异步 / 柔性阵列在当前预研路线里是 **P4**。它短期落地难度高，但研究价值不在“马上做产品”，而在把阵列观测从固定几何扩展到动态设备集合：手机、耳机、眼镜、笔记本、智能音箱都可能成为不稳定、多时钟、多拓扑的观测节点。

## 1. 核心问题

固定阵列假设同一采样时钟、固定几何、稳定通道顺序。分布式阵列相反：

- 每个设备采样时钟不同，存在 SRO / STO。
- 设备位置动态变化，几何不一定可知。
- 传输带宽和功耗有限，不能总传原始波形。
- 设备可能掉线、丢包、延迟不同。

## 2. 路线拆分

| 路线 | 代表 | 判断 |
|---|---|---|
| 异步鲁棒建模 | [[方向/AI语音/模型/SAMbA]] | 用注意力吸收 STO/SRO，不强行重同步；早期路线 |
| 压缩-发送 | [[方向/AI语音/模型/CaSNet]] | 端侧提特征并 SVD 压缩，只向融合中心传低秩表示 |
| 动态对齐注意力 | [[方向/AI语音/模型/SAMbA]]、[[方向/AI语音/模型/Windowed Cross-Attention（窗口交叉注意力异步阵列增强）|WCA]] | 处理多设备 SRO/STO 和动态位置 |

| 助听分布式双耳 | [[方向/AI语音/模型/RT-Tango]]、[[方向/AI语音/模型/Q-TANGO（量化分布式双耳语音增强）]] | 低功耗实时设备上的双耳分布式处理与量化 |

## 3. 预研价值

- **观测模型扩展**：从固定阵列的“多通道矩阵”扩展到动态设备图，研究大模型式环境感知可能需要的多节点音频表示。
- **几何不确定性**：SRO / STO、未知位置、设备移动和通道缺失可以逼迫模型学习更弱、更泛化的空间先验。
- **通信压缩接口**：CaSNet 式特征压缩可启发“端侧编码 + 云端大模型融合”的多设备音频链路。
- **动态 I/O 能力**：设备加入 / 退出、输入通道数变化、输出说话人数变化，是阵列无关和大模型接口都必须面对的问题。

## 4. 当前难点

- **真实系统变量太多**：同步、通信、能耗、隐私、动态设备加入退出都会影响实验可解释性。
- **benchmark 不成熟**：静态随机阵列不能代表真实 ad-hoc 设备网络，缺少统一的动态拓扑评测口径。
- **很容易退化成工程题**：如果过早锁定某个设备组合，会把问题变成通信协议和产品定义，而不是阵列建模。
- **和 P1 强耦合**：没有阵列无关表示，分布式路线容易变成每种设备组合单独训练。

## 5. 验证成本

- **同步成本**：SRO / STO 如果不处理，会破坏通道间相位和时延线索。
- **通信成本**：原始波形传输最贵；压缩特征要验证增强性能、隐私和鲁棒性。
- **拓扑成本**：中心式融合容易实现但有单点瓶颈；去中心化更复杂。
- **评估成本**：要测设备掉线、丢包、延迟抖动、动态位置，不只是静态随机阵列。

## 6. 当前跟踪顺序

1. **先跟 SRO / STO 动态对齐**：把异步和动态位置作为核心研究变量，而不是当作噪声预处理掉。
2. **再看压缩-发送接口**：CaSNet 式中心融合用于研究端侧表示如何传给云端 / 大模型融合器。
3. **最后看具体设备组合**：手机 + 耳机 + 眼镜等产品形态先作为 case study，不作为当前排序依据。

## 7. 关键来源

- [SAMbA](https://arxiv.org/abs/2307.16582)：异步 ad-hoc 阵列增强早期代表。
- [CaSNet](https://arxiv.org/abs/2601.17711)：压缩-发送分布式多设备增强，官方代码已开源。
