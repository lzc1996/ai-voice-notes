# AGC（自动增益控制）

## 0. 背景

AGC 出现之前，接收信号强度随距离、发射条件和说话人音量剧烈波动：早期无线电需要操作员手动旋增益旋钮，电话/扩声里说话人一靠近麦克风就过载削波、一远离就听不清。自动增益控制（最初称 Automatic Volume Control，AVC）在 1920 年代随无线电接收机普及，用闭环反馈把输出电平自动拉回目标范围，成为模拟时代的标准电路。

进入数字音频后，AGC 从硬件闭环变成语音前端的软件模块，并长出一条语音实时通信谱系：WebRTC 的 AGC1（固定数字 / 自适应模拟 / 自适应数字三模式，模拟模式直接调系统麦克风滑条）→ AGC2（输入音量控制器 + 自适应数字控制器 + 固定数字增益 + 限幅器，用语音活动分类器和语音电平估计器门控自适应，行业方向是把重活从模拟滑条移到数字路径）。它与响度标准化（离线、按节目响度）和动态范围压缩 DRC（压动态范围，不做平均电平闭环）相邻但目标不同。

## 1. 身份

`AGC`（Automatic Gain Control，自动增益控制）是让输出信号电平自动维持在目标范围的**闭环增益调节机制**：持续估计信号电平 → 与目标电平比较 → 按比例调整通道增益，使"说话人远近、声音大小"不再决定接收端听感。

最小闭环：

```text
input -> 电平估计（RMS/包络，带 attack/release 时间常数）
      -> 与目标电平比较 -> 增益计算（带上下限）
      -> 增益平滑 -> 受控输出（常配限幅器防削波）
      -> （反馈）输出电平回到电平估计
```

边界：AGC 只管**平均电平归一**，不是降噪（不区分信号与噪声，会把底噪一起抬）、不是动态范围压缩 DRC（压缩的是瞬时动态，AGC 调的是平均电平）、也不是离线响度标准化（如 EBU R128 按整段响度一次性归一，无实时闭环）。

## 2. 核心机制

核心量与公式（以数字 AGC 为例）：

- **电平估计**：对当前帧估计语音电平 $\hat{L}$（常用 RMS 或语音概率加权的分贝电平），时间常数决定抗抖动与跟随速度的折中。
- **目标电平**：期望输出电平 $L_{target}$（WebRTC AGC1 默认峰值目标 `target_level_dbfs = 3`，即距满刻度 3 dBFS，见 [[方向/AI语音/知识/基础概念/dBFS（满刻度分贝）|dBFS]]）。
- **增益计算**：$g = L_{target} - \hat{L}$（dB 域），再截断到允许范围——提升上限防止底噪被过度放大（AGC1 数字路径提升上限约 30–35 dB，AGC2 自适应数字控制器默认上限 50 dB 且要求输出噪声低于 −50 dBFS，超过即停止提升），衰减下限防止安静段被压死。
- **增益平滑**：限制增益变化速率（AGC2 默认最快 6 dB/s），避免"泵浦声/呼吸噪声"；attack/release 分别控制跟快峰与回落。
- **限幅器**：兜底防瞬时削波。

WebRTC 的两代实现：

- **AGC1**：三模式——固定数字（常数增益 + 限幅，嵌入设备）、自适应模拟（反馈环调 OS 麦克风滑条 0–255，桌面路径）、自适应数字（虚拟滑条，手机路径）；现归 legacy。
- **AGC2**：输入音量控制器（语音电平仅在约 −50 至 −12 dBFS 之外或检测到削波时才动模拟滑条）+ AEC/NS 之后的自适应数字控制器 + 固定数字增益 + 限幅器；内部用基于 GRU 的 RNN VAD 辅助判语音活动。两代不可同时开启（相当于二次增益）。

## 3. 在语音系统里的位置

```text
mic -> AEC -> NS -> AGC -> codec / ASR / 上行
```

- **顺序很硬**：WebRTC 把 AGC 放在 AEC 和 NS **之后**。AGC 在 AEC 前会改变回声路径增益、破坏线性回声模型（见 [[方向/AI语音/知识/基础概念/AEC（声学回声消除）|AEC]] 的非线性回声条目——扬声器削波与 AGC 本身就是非线性回声来源）；在 NS 前则把底噪一起放大，加重抑制负担。
- **多通道阵列要慎用逐通道 AGC**：各通道独立 AGC 会破坏通道间增益一致性，污染 [[方向/AI语音/知识/基础概念/ILD（双耳声级差）|ILD]] 一类通道间电平线索，也会改变波束形成的空间协方差结构；阵列前端的增益归一一般在通道校准层做，而不是逐通道闭环。
- **对 ASR 双刃**：训练数据已响度归一时，AGC 可能多余甚至引入泵浦伪影；远场低信噪比场景又可能靠 AGC 换取可用电平。是否启用要看测试口径。

## 4. 常见误读

- **AGC ≠ 音量键拉高**：目标是把不同距离/说话习惯的人声归一到稳定电平范围，不是无脑增益；盲目提升会把房间底噪同倍放大。
- **AGC ≠ DRC/压缩器**：压缩器压缩瞬时动态范围（让大声变小声），AGC 闭环调平均电平；两者常串联但目标不同。
- **AGC ≠ 响度归一化**：EBU R128 一类响度标准化是离线/单次测量，无实时反馈环；把两者混写会搞错时延与参数含义。
- **两套 AGC 并开 ≠ 双保险**：等于两次增益，音量忽大忽小甚至削波（WebRTC AGC1/AGC2 不可同开）。
- **时间常数不是越快越好**：太快会把字间停顿当电平变化，产生泵浦与噪声呼吸；太慢则跟不上说话人移动。

## 5. 相关对象

- [[方向/AI语音/知识/基础概念/AEC（声学回声消除）|AEC]]：链路顺序约束的直接对象；AGC 的非线性增益是 AEC 的失配来源之一。
- [[方向/AI语音/知识/基础概念/Level（电平）|Level（电平）]]：AGC 的控制对象；测量电平时 AGC 属于会改变读数的前处理。
- [[方向/AI语音/知识/基础概念/dBFS（满刻度分贝）|dBFS]]：数字 AGC 的目标电平与提升上限的计量单位。
- [[方向/AI语音/知识/基础概念/ILD（双耳声级差）|ILD]]：逐通道 AGC 会伪造通道间电平差的典型案例。
- [[方向/AI语音/知识/基础概念/Array Audio Signal（阵列音频信号）|Array Audio Signal]]：AGC 作为 WebRTC APM、XMOS、Shure 等前端 DSP 的标配模块出现在阵列信号链路里。
- [[方向/AI语音/知识/基础概念/ANC（主动降噪）|ANC]]：同样以"电平/幅度"为对象但机制完全不同的模块（声学抵消 vs 增益闭环）。
- [[方向/AI语音/评估/NISQA|NISQA]]：主观响度维度的评价会捕捉 AGC 造成的响度忽大忽小与压缩感。
