# Underwater-like Filtering（水下感滤波）

## 1. 定义与边界

**刻意把音频处理成"在水下"的听感**。两种用途，共用同一套知觉目标但实现口径不同：

- **数据增强的退化算子**：造合成的"水下语音传输"训练数据，让增强/识别模型对该条件鲁棒。
- **音效设计**：影视、游戏、氛围音里的下潜/出水效果。

三个容易混的边界，必须分清：

- **方向相反于 [[方向/AI语音/知识/基础概念/Boxy Sound（箱音）|箱音]] 这类伪影**。[[方向/AI语音/评估/OVRL_MOS|OVRL_MOS]] 把"水声"列为 `SIG` 退化、[[方向/AI语音/评估/NISQA|NISQA]] 把它列进 `Discontinuity`——那是增强算法**要消除**的失真。本页是**要制造**的效果。同一个听感，一个当 bug 一个当 feature。
- **不等于水声学物理**。DAS/DAGA 2025 明确声明「建模整个水下物理过于复杂」，只人工生成**噪声与混响**，因为这两项才是破坏质量与可懂度的主因。所以叫 "underwater-**like**"：抓知觉上起决定作用的几项，放弃完整的海洋声学建模。
- **不等于 [[方向/AI语音/知识/基础概念/Reverberation Modeling（混响建模）|混响建模]]**。混响是其中一环；水下感还要低通（介质吸收高频）+ 调制（水波流动）+ 通信链路带宽限制。

## 2. 两条路线

| | 音效设计路线 | 数据增强路线 |
|---|---|---|
| 目标 | **听感像** | **统计上覆盖真实退化** |
| 手段 | 低通 + 混响 + 合唱调制 + EQ | 信道冲激响应卷积 + 加性噪声 + 噪声源卷积 + 通信协议链路 |
| 参数来源 | 手工调 / 预设 | 环境几何 + 声速 + 吸收模型 |
| 是否需要可复现 | 否 | 是（要落元数据当标签） |
| 代表 | UnderwaterFX | Röhrdanz et al., DAS/DAGA 2025（基尔大学） |

## 3. 音效设计路线

**效果链**（UnderwaterFX 的实际实现）：custom low-pass filter + stereo chorus + spatial reverb，三块同时工作。

**参数**：

| 参数 | 作用 |
|---|---|
| Main FX | 宏旋钮，整体"下潜深度" |
| Dive | 低通截止频率 |
| Reso | 滤波器共振 |
| Chorus | 调制深度 |
| Reverb | 空间混响量 |

**常用参数区间**（来源为工具教程，属二手，仅作起点）：

- 低通截止 **500–1500 Hz**，斜率 **24–36 dB/oct**（越陡越"闷得假"）
- 短密混响，decay **0.3–0.6 s**，高 wet mix
- **200–400 Hz 提 +2~+4 dB**——补偿"低频在水里传得更远"的体感，不提会显得平
- 自动化过渡：**20 kHz → 500 Hz → 20 kHz**（下潜 / 出水）

**Chorus 值得单独说**：它模拟的不是频谱，而是**介质运动**。DAS/DAGA 那条路线里没有对应项，说明音效路线额外补了"水波流动"这个知觉线索——插件自述是 "Simulates the organic motion of underwater waves and widens the stereo image"。做增强退化算子时这一项要不要保留，取决于你要不要模型对介质时变鲁棒。

## 4. 数据增强路线（DAS/DAGA 2025）

```text
clean speech s(n)（LibriSpeech，1000+ 小时）
  -> 发射端处理（通信协议：MAD / STANAG）
  -> 信道：卷积环境冲激响应 h_env(n) + 加性噪声 + 噪声源卷积
  -> 接收端处理（解调 / 重合成）
  -> 退化语音
```

- **混响**：干净语音与环境冲激响应卷积——

$$
s_{\text{reverb}}(n) = s(n) * h_{\text{env}}(n)
$$

  $h_{\text{env}}$ 由环境几何 + 收发位置决定，用**镜像声源法**（见 [[方向/AI语音/知识/基础概念/ISM（Image Source Method，镜像声源法）|ISM]]）计算：每个反射面有反射系数 $\alpha_r$，对每个声源在每次反射处生成等价镜像声源。

- **镜像声源的三条有效性条件**：① 镜像声源到关注点的连线必须穿过生成它的那个面；② 该连线不得穿过其它面；③ 镜像声源到接收端的距离必须大于直达成对距离。不满足的镜像源剔除后，剩下的合成 $h_{\text{env}}$。

- **时延**：信号走含多次反射的路径所需时间，由镜像声源到接收端的距离 $d$ 与声速 $c$ 决定——

$$
\tau = \frac{d}{c}
$$

- **每次反射带来 180° 相移**，并按反射/吸收系数衰减；此外还计入 **François–Garrison 吸收模型**与**球面/柱面扩展损失**。
- 论文示例最多计算 **8 次反射**。

**通信协议链路**（这是容易被忽略的一层——只做混响+噪声会漏掉带限和调制伪影）：

- **STANAG**（NATO 标准）：对 $s(n)$ 施加 **300 Hz–3 kHz 带通**，再经单边带调制（SSB）搬移到 **8087.5 Hz**；接收端 SSB 解调。
- **MAD**（Mixed Analog Digital）：发射端白化 + 功率归一化，参数用低阶码本做（矢量）量化以降速率；接收端重合成。

**论文自陈的取舍**：只建模噪声与混响，不管完整物理；说话人多样性靠 LibriSpeech（1000+ 小时男女声）；环境多样性靠随机场景（示例用德国基尔 WTD 71 港，含发射节点、接收节点和发出舰船声的主动噪声源）。论文还指出**传输时延**在纯声学通信下无法避免，会影响对话节奏——做增强时这是内容之外、必须单独处理的一项。

## 5. 在 vault 里的位置

这个算子补进已有的退化体系，两处都缺它：

- [[方向/AI语音/知识/基础概念/音频数据预处理|音频数据预处理]] §9 数据增强表目前只有 Mix/加噪、RIR 卷积、speed perturbation、pitch shift。本页可看作 **RIR 卷积的特例化 + 低通 + 介质调制 + 链路带限**的复合算子。
- [[方向/AI语音/知识/技术路线/LLM-SE Stage 2（多退化条件重建）|LLM-SE Stage 2]] §6 的退化桶清单（additive noise / reverberation / bandwidth limitation / codec artifact / clipping / packet loss / wind noise / overlapping speaker / real-world）没有对应桶。若接入，按该笔记的规则，**噪声类型 / SNR / RT60 / 带宽 / codec 类型要在加噪时落盘**——水下感退化同样要落自己的元数据（截止频率、反射次数、协议）。

接入时的一个约束继承自该笔记：**退化强度上限 = 内容仍可辨认**。水下感很容易调过头把内容毁掉，届时不只增强失败，显式一致性 loss 的假设也会断裂。

## 8. 待验证

- **UnderwaterFX 未标注许可证**。GitHub README 没有 license 字段，仓库页面也未声明开源协议——「免费开源」的说法来自第三方报道，商用前必须自己确认。
- **音效路线的参数缺权威出处**。低通截止、混响 decay、低中频提升的具体区间全部来自教程，没有 DSP 教材或论文级来源。若要做成可复现的退化算子，需要自己标定。
- **两条路线的听感对齐**：音效路线（低通+合唱+混响）与信道路线（IR 卷积+协议链路）产出的是否是同一种"水下感"，没有对比研究。
- **退化强度上限的标定**：截止频率降到多少、反射次数取几次会让内容不可辨认，需要自己的听力/ASR 抽检确定。
- **时延项是否纳入**：DAS/DAGA 把传输时延列为不可避免的实际效应，但增强模型通常不做时延对齐——这项要不要进训练数据待定。
- **是否需要单独建 UnderwaterFX 对象页**：若后续真的用它做管线组件，再拆到 `工具/`。
